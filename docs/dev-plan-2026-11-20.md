## 背景：为什么现在后台进不去

三个登录方式本身都指向同一张 `user` 表，但**用不同的键找人，且没有做跨渠道绑定**：

| 登录方式 | 匹配键 |
|---|---|
| 账号密码 | `user_info.phone` |
| 小程序扫码 | 小程序会话的 `userId` |
| 网页微信登录 | 微信 `openid`（`account.providerAccountId`） |

结果：同一个人被拆成多条记录。以 `Gahon` 为例，生产库里有 **3 条**：

| user.id | 绑定 | 手机号 | 角色 |
|---|---|---|---|
| `95f967e5-…` | `wechat-miniapp` | 176****3562 | admin |
| `47c74397-…` | `wechat-open`（网页微信） | 无 | admin |
| `be382afc-…` | 无绑定 | 无 | admin |

- 小程序扫码、账号密码 → 命中 `95f967e5`
- 网页微信登录 → 命中 `47c74397`（openid 独立建号）

**当前完全登不进去的直接原因**：`user_credentials` 表里 **0 条记录**，密码登录无密码可比对。

### 任务 1｜写入管理员密码　`P0 · 今天 · 约 5 分钟`

**现状**：`user_credentials` 为空，任何密码都登录失败。

**目标**：主管理员号能用账号密码登录后台。

**步骤**
1. 在 Cloudflare D1（`diceshock` 库）执行：
   ```sql
   INSERT INTO user_credentials
     (user_id, password_hash, algorithm, salt, iterations, created_at, updated_at)
   VALUES
     ('95f967e5-194d-46f8-84b2-159bffa7a90e',
      '<PBKDF2 哈希：见内部交接>',
      'PBKDF2-SHA256',
      '<盐值：见内部交接>',
      600000, 1795000000000, 1795000000000)
   ON CONFLICT(user_id) DO UPDATE SET
     password_hash = excluded.password_hash,
     salt = excluded.salt,
     iterations = excluded.iterations,
     updated_at = excluded.updated_at;
   ```
2. 登录 `https://diceshock.com/login`，账号 `176****3562`，密码 `<管理员密码：见内部交接>`

**验收**：登录后进入 `/dash`，右上角账号显示为管理员。

**风险**：低。写错可 `DELETE FROM user_credentials WHERE user_id='95f967e5-…'` 回滚。

**负责**：伙伴（有生产写权限）或你在 Cloudflare 控制台执行。

### 任务 2｜合并重复账号　`P1 · 本周 · 约 1 小时（含备份）`

**现状**：一人多号。`Gahon` 3 个、`nerd` 2 个，另有多个微信自动建的号。

**目标**：一人一号，三种登录方式落到同一个 `users.id`。

**步骤**
1. 备份：`wrangler d1 time-travel info diceshock` 记下 bookmark
2. 把重复号的第三方绑定挪到主号：
   ```sql
   UPDATE account
   SET userId = '95f967e5-194d-46f8-84b2-159bffa7a90e'
   WHERE userId IN ('47c74397-f62d-465c-bd31-14ad15dbcc12',
                    'be382afc-a3f9-48ff-91f5-e5da34896162');
   ```
3. 校验绑定数量符合预期（grep `account` 表）
4. 确认无引用后删除重复的 `user_info` 与 `user` 记录

**验收**：用小程序、网页微信、账号密码三种方式登录，`/api/auth/session` 返回的 `id` 相同。

**风险**：中。涉及 `account` 表，务必先备份；删除 user 前确认没有业务数据（报名、订单）挂在旧 id 上。

**负责**：伙伴（写权限）+ 我提供 SQL 与校验脚本。

### 任务 3｜登录后强制绑定手机号　`P2 · 下个迭代 · 约 1 天`

**现状**：网页微信 openid 拿不到手机号，登录时直接新建无手机号账号 —— 这是重复号的根源。

**目标**：网页微信登录成功后，若账号无手机号，引导验证手机号，并按手机号合并到已有账号。

**步骤**
1. 在 `apps/diceshock/src/server/middlewares/auth.ts` 的登录回调里检测「无手机号」
2. 新增「绑定手机号」页面与接口（复用现有短信验证码能力）
3. 验证成功后：按 `user_info.phone` 查找主号 → 迁移 `account` 绑定 → 清理临时号
4. 补测试：覆盖「新用户绑定」「老用户合并」「手机号冲突」三种情况

**验收**：用未绑定过的微信登录 → 强制走绑定流程 → 完成后与已有账号是同一 `users.id`。

**风险**：中高。改动认证主流程，需在 staging 完整验证后再上线。

**负责**：开发（可指派给我）。

### 任务 4｜后台隐藏微信登录入口　`P2 · 可选 · 约 30 分钟`

**目标**：后台只保留「账号密码」与「小程序扫码」；微信登录仅用于前台会员。

**步骤**：`apps/diceshock/src/apps/routers/{-$storeLocale}/login.tsx` 里按需隐藏 `wechat` tab。

**验收**：后台登录页只剩两个入口，前台会员登录不受影响。

**风险**：低。

**负责**：开发（可指派给我）。
